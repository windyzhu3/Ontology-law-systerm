## 保持的业务与设计约束

- 从导入结果进入 R1 已有的去重、补齐、分配和首联。有效联系形成商机；不另造导入即直接合同的捷径。
- 保留正式报价；直接合同只能来自有权人员对准确商机、范围和收费条款的授权，两路径汇合。授权不代替合同审批和签署。
- 原责任完成后创建新责任。未来跟进等待到约定时间由可靠调度唤醒，不复用旧任务或重置 SLA；跨角色事项真实交给相应负责人。
- 报价草案、审批、交付、客户接受分别成立。原型展示有证据的人工交付方向；实际交付事实合同仍需具名实现，不以勾选框直接替代证据持久化。
- 人工签字件是 R2 默认路线。提交文件不等于核验通过；全部必需签署、用印、归档满足后才形成执行事实。场景 33 集中展示汇合，生产仍保留各独立责任与事实。
- 只有合同明确约定先到账时阻断转案；客户截图不等于到账；接收建案不自动记账。
- 案管审核接收后生成一次案件，再分类为综法、执行或其他。销售合同准备不出现案件分类。
- AI 仅字段提取、跟进摘要、材料缺项提示。摘要演示人工修改、确认、忽略和来源变化失效；缺项提示不替代确定性材料检查。
- 沿用 B 包 CSS 基础及现有颜色、6px 圆角、弱阴影、管理侧栏、列表详情、单工作卡和单一主操作。未保存切换有保护。
- 不新增电子签、渠道消息平台、专业案件办理、完整财务总账或通用工作流编辑器。

## 尚未被本原型证明的实现

本轮没有新增生产业务命令、迁移或消费者。研发顺序必须按以下可执行切片推进，不能再将接口、空卡或此原型视为业务已完成：

1. **R1 → 商机跟进。** 进展正文的受保护事实存储和读取；准确命令、草稿、回执、权限、工作卡；首次责任的可靠生产激活与历史接续；完成后创建有因果关联的后继责任及可靠到期唤醒；Owner 失效形成持久异常。相关现有入口见 `OpportunityTaskActivationService`，当前仍未激活生产消费者。
2. **商机 → 两种合同来源。** 准确报价版本、审批、交付证据、回复事实及新责任；直接授权来源；商机/报价管理页面只查询真实状态。拒绝、仍在考虑和不明确分别派生责任。
3. **合同 → 签署可执行。** 可用完整合同文件、冲突审查、准确版本审批、人工签字件上传与核验、必需用印及归档。退回或正文变化必须创建新版本，旧批准和旧证据不得错用。
4. **执行 → 接收建案。** 合同条件判定、独立收款、转案材料、案管退回补正、幂等接收建案、建案后分类。
5. **管理与全链回归。** 在每片同步接入本人/跨负责人/等待/异常查询；最终以同一批真实业务事实从导入通过签约、接收和分类验证。两入口、两付款分支、退回、新版失效、重复提交、未知结果、撤权和历史 R1 商机都必须覆盖。

团队恢复操作、完整合同文件、实际材料上传预览和可靠服务均未由此原型实现。团队异常页当前只覆盖查询披露，不批准未定义的任意改 Owner 或后台改阶段动作。R1 验收继续 PAUSED，R2 不据此标记通过。
