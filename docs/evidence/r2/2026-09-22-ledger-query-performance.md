# R2 商机与合同台账查询性能

## 范围与约束

用户要求修正两类台账查询慢。沿用冻结界面、原有列表字段、分页、权限与业务流程；不通过缩小返回范围或跨请求缓存权限来提速。

## 复现与根因

账号 task9-local-contact，页面验收组（合成数据），通过真实 HTTPS API 读取同一批数据。初始商机列表 17 条，三次 7.825 / 6.871 / 8.432 秒；合同列表 9 条，三次 10.579 / 9.440 / 9.652 秒。

1. 锁后每个事实授权仍重复发出获取同一事务共享身份锁的 SQL。单记录隔离测试商机 35 次、合同 109 次共享锁请求（含业务锁）。
2. 选取有效授权路径后再次执行同一评价，产生额外数据库时间查询。
3. 合同列表逐行复核后又整页复核，重复读取同样事实；商机在业务和身份锁内完整构建两次上下文。
4. 相同负责人的原始身份信息在同一请求内被反复读取。
5. 搜索输入每次变化立即发起服务端查询，快速输入放大了昂贵请求。

## 实施

- 已持有的身份共享锁只获取一次。scope 键仍绑定线程、连接和租户，不在其他事务跳过锁。
- R1AuthorityReader 提供一次完成选取与最终评价的授权读取，台账及合同内部资格判断复用；不缓存允许/拒绝决定，每次评价仍从数据库取当前时间。
- 合同列表在读取内容前完整收集准确来源和授权证据，在业务 fence 与身份锁内构建一次；返回前保留当前时间权限和任务核验及同步审计，不重复构建不能在锁内被业务写入修改的来源图。
- 商机在业务 fence 和身份锁内构建一次。CommandRuntime 的所有业务命令写入均先取排他业务 fence，读持共享 fence 至提交；保留最终当前权限和时间评价，不复建整页上下文。
- WorkcardOwnerReader 仅在已持有身份锁的一次读取 scope 中复用原始 Owner 记录，包含有效时间字段；有效性仍由调用方按当前时间计算，scope 关闭立即丢弃。
- 搜索合并 250ms 连续输入，立即清除旧选择并取消旧请求；依然由服务端负责搜索与权限过滤。
- 没有引入 Redis，没有缓存完整台账或授权结论。
