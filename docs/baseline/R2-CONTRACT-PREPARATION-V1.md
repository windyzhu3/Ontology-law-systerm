## 双入口

合同准备来源只能是准确已接受报价，或准确直接准备授权。两者互斥且均绑定租户、商机、客户确认及商业范围内容。直接授权的申请、决定必须有独立事实，不能生成虚构 QuoteResponse。

报价来源要求准确版本、已交付事实、接受回应及证据；接受发生在交付后且严格早于报价有效期结束。当前读取时间已经超过报价有效期，不抹除过去合法接受。最终读取仍检查来源事实真实性、未撤销/未被后继替代、商机状态和授权。

直接授权只有有权者对准确申请的批准有效；有效期使用可信数据库当前时间，每次准备重验。主体、范围、费用或客户确认变化不能沿用旧决定。纯输入类型不能替代决定存在性、批准状态或权限检查。

## 准备与审查顺序

L 确认流程为：形成准备版本 → 提交签约前审查 → 冲突结论 → 合同审批 → 签署准备。既有 contract_revision 强制已解决 PRE_CONTRACT 与此顺序不同。持久化实施必须追加具名演进，把准备正文及准确版本与后续审查决定分别记录；没有准确有效审查与全部批准，禁止签署准备放行。不能写入假结论，也不能修改已封存正文补入结论。

既有合同锚点及版本仍为唯一真源；字段合同、约束、触发器、引用登记、运行验证和部署门禁必须同批更新。迁移不激活前，现有强制非空字段继续有效，不能以应用层 DTO 绕过。

## 付款与签署

每版固定委托主体、服务范围、精确费用、付款安排、签署与归档要求、模板/条款及正文摘要。付款门禁为明确合同约定，不能按销售阶段或未来案件分类推断。只有明确要求先到账的合同才阻断转案；本工作包不伪造到账、合同执行或案件身份。

## 安全与后继

保留原授权、审计、幂等和业务锁顺序。重复接受事件/命令只生成一次准备责任；改版、退回、补充形成新事实和责任。无负责人可恢复，原命令结果未知使用同回执核对。提交审批不等于签署，不创建无实际处理入口的占位任务。

## 首批代码边界

ContractPreparationSource 与 ContractVersionInput 为已实现的纯 Java 输入规则。`R2_CONTRACT_PREPARATION_V1_COMMERCIAL` 摘要覆盖 CNY、范围、精确计价行、条件收费、付款条款；准备包摘要额外覆盖合同身份/版本链、准确来源、正文证据版本/字节摘要、模板/条款版本、参与方快照、签署要求和收款门禁。采用项目既有整数 JSON 子集的规范序列化与 SHA-256；不能把该商业摘要当成既有 QuotePackage 的完整摘要，两者语义不同，持久化适配必须从准确报价事实提取并比对商业条款。

输入校验不验证数据库引用存在性、直接决定是否已批准、模板是否已审核、文件字节是否真实、当前主体/权限或版本是否最新；这些是后续持久化与命令事务的强制责任。构造成功不创建合同、不创建待办，不放行签署。正式 API 不允许由客户端提供“已批准”的来源证明代替 Owner 读取。

## 准备来源的数据库复验

`ContractPreparationSources.resolve` 接收互斥的报价回应或直接决定标识，从真实数据库还原来源。它要求调用方持有 READ COMMITTED、非自动提交的命令事务，先锁同租户商机，再检查当前客户确认，并按稳定顺序锁定参与主体、核对冻结修订与 ACTIVE 状态；报价还锁准确 Issue。直接来源必须是当前准确申请的 APPROVED 决定，商业摘要、客户确认、商机修订和责任依据一致。有效期使用锁等待及读取完成后的数据库当前时间，不能以进入请求时的时间延长授权。

报价来源接续 T07 的实际准备来源、接受回应、Issue、不可变报价包及 T06 证明版本；不支持用缺少 T07 完整依据的旧数据直接补成成功。交付和接受证明均锁定准确 EvidenceBinding 并复验未撤回，历史曾经可用不能代替当前有效性。校验正文解密后的 SHA-256 同时等于保存依据及报价版本摘要，再由受信任 API 组合适配器提取商业条款，计算合同商业摘要。报价完整摘要和合同商业摘要分别验证，不能互换。合法接受以实际交付、接受及记录时间判断，当前自然到期不清除该事实。

此服务尚未注册为 HTTP 或业务命令，不自行完成身份授权、敏感读取审计、合同写入或后继责任；返回对象只在同一个受控事务内作为写入前依据，不是可缓存或由客户端提交的批准凭据。后续命令必须按原机制锁定并重验全部授权依赖、同步审计，并在实际写入边界再次确认来源与时间。既有合同锚点及 PRE_CONTRACT 强制字段尚未演进，不能用此读取服务绕过它们。
