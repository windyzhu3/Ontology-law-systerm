## 1. 冻结来源与当前有效责任

Opportunity.Owner 与来源 Assignment 是形成商机时的冻结来源事实，交接不得修改。拟新增不可变 `opportunity.responsibility_handoff`，记录同租户商机准确引用、原责任basis、新接收任职、操作者、异常/处置准确引用、可空旧任务、必需新任务、原期限和可空原等待引用、交接时刻。交接不创建或替换原Assignment，不重新记录联系，不伪造进展。

具名口 `OpportunityResponsibilityReader.current(Connection, UUID tenant, Subject opportunity)` 拟返回 `Responsibility(Subject basis, UUID appointmentId)`。没有交接时basis为经验证的原商机责任依据、appointment为冻结Owner；有交接时沿准确前任链取唯一末端交接事实与接收人。每个 `(tenant, opportunity, prior responsibility basis)` 只能有一个后继，严禁分叉、循环、跨商机或跨租户。查到分叉/坏引用必须失败关闭并进入受控异常修复，不任选最新时间一条。

读取调用者提供的商机必须是当前允许使用的准确版本；来源身份与交接basis须均能解析。后续商机版本变化不能丢失已建立责任链或回退到原Owner；其支持规则必须随对应商机版本合同注册，未注册的版本变化拒绝，不猜测自动迁移。

工作卡、草稿写入/提交、人工进展、首次激活、INITIAL/DUE候选、等待恢复和命令原结果保护都必须统一使用此口。来源核验继续检查原Owner/Assignment；执行资格检查当前basis与任职，不以放宽原Owner等式替代。basis是工作卡受保护源及前置版本的一部分，交接后旧卡ETag必须失效。

## 2. 正式交接前提与接收资格

拟命令 `TRANSFER_OPPORTUNITY_RESPONSIBILITY` 仅允许有 `OPPORTUNITY_OWNER_EXCEPTION_RESOLVE` 的当前 HUMAN 所选任职；输入封闭为异常准确ID/revision、商机准确Subject、期望责任basis、可空期望任务与等待Subject、目标任职ID和规范原因（1–2000字符）。tenant/actor由可信会话决定，不接受浏览器任意主体、期限、状态、权限或草稿内容。

必须在商机根锁下确认异常活动、来源完整、商机未关闭、责任basis一致。`SOURCE_INCONSISTENT` 不能靠转派消除；应先通过对应来源Owner的受控修复，不属于本命令范围。目标必须同租户有效HUMAN主体/任职/组织，当前已经有SALES_OPPORTUNITY_OWNER，对商机及后续办理所需来源/任务/等待/进展事实无DENY。交给当前有效责任人不生成伪交接，可返回有审计NO_CHANGE，异常是否可解决另按正式观察规则判断。

前端候选只是授权查询结果。锁等待中任职到期、授权撤销、对象DENY或目标变化，最终复验失败全回滚。两主管同版本交给不同人时仅一个成功；另一个得到过期结果，不自动改为转派赢家的新责任。

## 3. 任务状态与期限矩阵

| 交接时准确现状 | 责任动作 | 期限/等待要求 |
|---|---|---|
| 从未存在初始任务，来源完整 | 由专用初始交接入口创建唯一OPEN初始任务，冻结新有效责任basis | 从数据库真实承接时刻按既有业务时区/日历计算R2_BUSINESS_4H_V1，14400业务秒；不从历史商机创建时刻起算 |
| 当前任务OPEN | 旧任务以准确交接依据进入CANCELLED；创建独立OPEN交接接续任务 | 原SLA契约、原截止时刻完整继承，不因换人重置；已逾期仍逾期 |
| 当前任务WAITING，尚未到期 | 旧任务以准确交接依据进入CANCELLED；新任务保持WAITING并持有具名交接等待依据 | 保留原resumeDue、原期限和准确原wait/progress来源；不提前OPEN，不从交接时间重算 |
| 当前任务WAITING，已经到期 | 仍原子建立新WAITING责任及准确继承依据；交由正式到期恢复命令恢复 | 到期判断使用数据库时钟；交接命令不兼任唤醒，原期限保持 |
| 当前根已DONE/CANCELLED且有合法活动后继 | 对准确活动后继交接 | 不动旧终态及其历史，按活动后继OPEN/WAITING规则处理 |
| 仅有终态且无可验证合法活动后继 | 拒绝此交接；具名异常协调修复 | 不重开旧卡，不将“已有终态”当首次创建 |
| 商机关闭/异常已终态/期望版本变化 | 拒绝旧交接请求或恢复原回执 | 不造新任务，不更改旧期限 |

旧任务CANCELLED必须引用真实handoff/决定作为取消依据，不能填completion为`opportunity_progress`或调用complete制造DONE。拟Responsibility专用 `handoffOpportunityTask(...)` 独占任务状态与关系写入；现有守卫不支持此变化时先注册具名schema后继，再实现，绝不禁用守卫。

新接续任务用独立handoff relation识别，与现有“DONE进展后继”的predecessor区分。初始唯一性必须只承认一条起始身份并识别交接接续；不能把每张无进展前序的交接卡误认为初始任务。原初始卡无论终态仍占其历史身份，普通create入口继续不得绕过。

新WAITING需要具名 `R2_OPPORTUNITY_HANDOFF_WAIT_V1` 继承依据（拟注册）：绑定handoff、新任务准确修订、原等待、原完成进展、原resumeDue和原期限。到期恢复分别核验普通跟进与该具名交接链；不能把已CANCELLED旧卡冒充DONE前序。恢复仅将新同一任务OPEN并递增修订，不生成又一张任务、不改期限。连续多次交接沿有界且可验证链确认原等待依据；本草案限定单次最多核验64条交接引用；超限返回受控修复，不跳过核验。增加上限须单独修订合同，不进行无界递归。

## 4. 草稿、历史及后继办理

新任务有新的任务ID与空草稿空间；不复制、改Owner或重绑定旧ActionDraft，不能把旧人未提交内容显示为新人的已保存输入。旧草稿保留其历史归属，读取仍按旧事实当前授权，不因接收责任自动披露。

新人必须重新人工确认其自己的进展输入。提交后按现有进展合同产生真实进展、完成新卡、创建后继；后继Owner为当前有效责任，并带准确basis。再次交接必须消费该当前basis；旧人即使保留某些组织权限也不得提交已取消旧卡。受保护进展等正式历史事实仍按所需权限读取，不能因禁止草稿复用而丢失合法来源。

## 5. 同事务结果与恢复

复用CommandRuntime当前授权、业务fence、身份锁、商机根锁、命令锁与最终授权提交边界；Responsibility口在其内部锁任务，所有交接/推进/恢复遵守一致锁顺序。Root锁后重读异常、basis、旧任务与等待。数据库活动周期唯一约束与前任唯一后继约束兜底，不能仅靠浏览器禁用按钮。

一次成功事务形成不可变TRANSFER disposition、handoff、旧卡准确取消、新任务/等待依据、异常RESOLVED引用、审计、正式回执及既有可靠事件通道中的具名事件。所有事实相互引用必须可在提交前准确解析；生成ID与写入顺序由模块Owner协调，不靠后续补写修复循环引用。任何一步失败均回滚，不出现异常已解决但新人无卡。

幂等scope拟为 `R2_OPPORTUNITY_RESPONSIBILITY_HANDOFF_SCOPE_V1`，绑定tenant、商机与异常周期；同键同规范正文恢复原回执，同键异正文冲突。协调使用独立scope，不能共享交接键。不同键抢同准确basis仍只一个后继。原回包丢失后必须重放原键原输入或经授权读取原命令结果；恢复不再次运行交接，不自动更新为当前候选或当前版本。

恢复仍核对当前操作者任职/权限与resultFact所引用准确历史版本及当前对象保护；没有当前披露权限不能看到历史结果。跨身份/跨租户命令ID不能读取。成功后刷新准确异常和新待办再显示结果，禁止以HTTP成功或按钮点击作为完成依据。

## 6. 查询与验收

主管详情返回其权限内的原责任、当前责任、期限、等待时间、异常理由及可执行动作。只读用户只读，运营走异常合同独立受限摘要，无候选或处置入口。交接确认显示接收人、原期限是否逾期、等待不会提前恢复与需要新人重新输入；未知结果提供原结果核对，不诱导新键重提。对应缺失HF须用户确认后实施页面。

| 验收 | 准确预期 |
|---|---|
| 历史无卡交接 | 仅一次初始身份，按首次真实承接业务日历起算 |
| OPEN/逾期交接 | 原卡取消且有交接依据，新卡继承原截止，原业务Owner不变 |
| 未到期/已到期WAITING交接 | 新卡先保留WAITING；唯有正式服务到期恢复OPEN，期限不变 |
| 原人推进与主管交接同时发生 | 商机锁串行，只有一个准确版本成功；无虚构进展/孤立卡 |
| 两目标竞争与回包丢失 | 一个handoff/新卡；原键恢复同一结果 |
| 新人打开/保存/提交 | 无旧草稿，实际产生自己的真实进展与合法后继 |
| 初始已终态或链损坏 | 不重开、不另造初始身份，失败关闭且可协调 |
| 当前权限撤销/候选失效/DENY | 写入回滚，读与回执恢复不泄漏 |
| 数据验收 | 原Opportunity.Owner/Assignment不变；旧期限/等待与历史完整；无伪造DONE |

上述为待实现验收合同，未执行生产验证，不改变R2发布验收状态。
