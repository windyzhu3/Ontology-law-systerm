# 审计记录查询实施设计

状态：用户已确认查询版实施计划，由当前会话逐项实施。2026-10-02 用户明确收窄为“只做查询，不做导出”；下述范围取代此前补充设计中的导出内容。

## 目标与依据

在现有 SPA 管理模式提供审计轨迹查询和只读详情，帮助获权人员核对实际操作人、采用任职、授权路径、结果和关联轨迹。沿用共同顶栏、侧栏、tokens、列表及右侧详情布局。

依据为 `docs/design/identity-admin-mvp/README.md` 的 ADM-07、历史提交 `72a83b810339095a6ebefd11b30cf7fc8f522eec` 的冻结图片，以及当前 MVP 基线、52＋2 字段与运行时合同。此前 Task9 未实施审计浏览，本次是独立增量。原图片中的导出控件本次不实现。

已有不可变 `audit.audit_entry`、分类视图、审计追加端口及四轴授权服务；缺少审计浏览 API、专用权限和菜单入口。本设计补齐这些实施合同，不把历史视觉确认当作接口已经存在的证据。

## 本次范围

- 一张“审计记录”只读页，同一 SPA 和管理侧栏，无独立管理应用。
- 按服务端可信时间、审计范围分类和结果查询，支持获权安全显示名称及静态对象类别搜索。
- 列表显示可信时间、操作人、动作、业务对象类别、范围、授权路径和结果。
- 右侧显示实际任职、记录时组织范围、代办情况和允许列表业务摘要。相关操作链及既有更正链仅只读查询，每次重新鉴权并先审计后披露。
- 没有导出权限、导出 API、CSV、文件下载、导出按钮或禁用占位入口。
- 没有新增／编辑／删除／更正命令、业务重试、回滚或回执办理；不实施 ADM-05／06，不建设搜索服务或运营看板。

## 独立任职权限

新增静态 `AUDIT_READ` 权限，仅显式授予具体任职，冻结组织范围和有效期。查询、详情和关联链均要求该权限；原身份管理、主管、财务和案管权限不能替代，岗位不会自动赋权。

只允许当前有效 HUMAN 本人任职，SERVICE 和代办拒绝。新增可选资格提示 `canReadAuditRecords`；既有身份管理资格语义保留。审计专用任职进入管理模式后默认落到审计页，不能因此读取身份主体或任职目录。

组织授权只覆盖记录组织范围属于当前获权范围的条目。没有安全可判定组织范围的租户／系统条目需要根组织授权。“全部范围”只是获权结果内的分类筛选，不能扩大授权，不能按操作人所属部门猜测记录范围。

每条披露判断准确审计事实与记录的准确业务 Subject，执行当前四轴鉴权、对象 DENY 和组织范围限制，披露前重新检查授权撤销／到期、任职、主体与组织变化。不可安全分类或无法判定范围的来源不披露。

不自动赋权 `sys_manager01`。正式权限由另一位拥有现有授权管理资格的管理员通过准确直接授权显式授予，不执行业务 SQL 写入、不绕过自授权限制。验收可临时向合成 `sales05` 的销售二部范围授予 `AUDIT_READ`，验证后撤销；根范围正向和越租户反例在独立真实 PostgreSQL／HTTP 夹具验证。

## 安全投影

不直接披露整个 `change_summary`、`authorizationEvidence` 或恢复元数据。摘要完整性由 Audit Owner 核验，再按注册 schema 提取允许字段并转换业务说明。未知 schema 只显示安全动作和结果，不返回原始 JSON。

不能安全取得对象名称时显示静态对象类别，不补查无权业务正文，不使用 UUID 充当名称。不得披露会话 HMAC、客户端 IP 密文、执行节点、自然键 HMAC、Token、Secret、个人联系方式或法律正文。

“技术校验信息”只显示经过核验的完整性、记录类型和安全关联状态。更正链只呈现已存在的不可变更正事实，没有更正入口；不返回未授权关联节点计数。

## 查询与审计事务

Query Facade 调用 Audit Owner 窄读取端口，仅查询 `audit.audit_entry_classified_v`，禁止读取基表或扩大数据库 GRANT。保持 52＋2 表数，不新增查询表、物化视图或后台任务。

沿用 READ COMMITTED、Tenant 业务共享栅栏、身份共享锁及 QUERY／AUDIT capability 切换。先核验查询资格，再读取有界候选并逐条授权、最小投影和最终数据库时钟复验；同步写入本次查询／详情／关联链的独立披露审计并确认提交后才返回内容。审计追加失败或提交未知，任何条目都不返回。

审计查询不继承命令回执恢复的特殊非递归元数据例外。每次有界披露写一条审计，不递归查询自己刚写的条目，不创建业务 Command、Receipt、Event、Outbox 或责任。

## 有界筛选与分页

默认最近 7 天，服务端校验起止，单次最长 31 天；每页默认 20、最多 50 条；搜索最多 100 字符。范围及结果是静态分类，不让客户端选择 SQL、权限代码或授权事实。

采用可信时间和条目标识的稳定 keyset 游标，绑定 Actor、筛选、当前授权依赖与查询时间水位；不用 offset，不显示全目录总量、总页数或跳页。后续页不会因本次查询追加的审计记录漂移。关联链、更正链同样有界分页。

筛选变化重新查询，清除选中详情、前页游标和关联链。任职、租户或登录身份变化立即清除数据。401／403 不等待脏表单确认，错误信息不泄漏目标是否存在。刷新只是新查询，也必须先审计后披露，没有自动循环重试。

## 接口和兼容约束

新增封闭查询合同、生成类型和最小 DTO，复用现有认证与资格检查。接口包括列表、单条只读详情、相关操作链和既有更正链查询；没有审计写入或导出 HTTP 端点。

`AUDIT_READ` 进入既有可授予静态权限清单并增加业务标签，不加入管理员初始化自动授权集。不改变既有管理命令、生命周期、幂等恢复、审计物理字段或历史迁移字节。

仅按本次具名新增 OpenAPI 路径、DTO、权限枚举和可选资格提示制作准确 successor 投影与反例测试；不修改旧门禁使其虚假通过。

## 完成验收

- 界面对照 ADM-07；共用菜单和顶栏，统一按钮、键盘焦点及响应式布局，没有任何导出或写操作。
- 无权、越租户／组织、SERVICE、代办、失效任职、权限到期／撤销和 DENY 均不披露；审计专用资格不带来身份管理读写权限。
- 列表、详情、关联链、错误和披露审计均不包含禁止字段或完整摘要 JSON。
- 时间／范围／结果／安全名称搜索、稳定分页和 Actor 游标绑定正确，更正事实不修改。
- 审计失败／提交未知时无响应内容；真实 PostgreSQL 验证查询角色不能 SELECT 基表，不扩大 GRANT。
- 不改变旧业务 Command／Receipt／Audit／Event／Outbox 基数；原登录、身份管理、批量授权和审计写入回归通过。
- 保存海华环境和原业务数据，部署前备份并绑定制品；临时验收授权最终撤销。没有显式审计授权的账号维持无权读取，不为了演示自动扩权。
