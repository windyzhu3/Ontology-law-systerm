# R2 T03 商机台账与办理接续 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Missing UI states require the user's prior high-fidelity confirmation. Do not commit or deploy automatically.

**Goal:** 销售和主管在授权范围查看正常商机当前责任、最近进展与下一事项，并进入本人有权办理的既有工作卡。

**Architecture:** Owner具名只读端口提供有界列表及准确详情；服务端完成身份、组织、准确事实披露授权和审计，再生成最小投影。办理入口沿用现有任务选择及工作卡命令，不从台账直接写业务状态。有效责任复用T01，自动任务接续复用T02。

**Tech Stack:** Java25 / 既有CommandRuntime及读取审计 / OpenAPI / React / 既有E母版CSS。

## 编号及范围依据

仓库已有T01、T02明细，没有独立T03任务文件；本轮将原总计划R2-2尚缺的正常商机台账登记为T03，不把编号当作此前已存在的合同。E场景07已批准正常列表详情；G只补该范围的缺失状态，不重新设计母版。

本项不实现商机关闭命令、报价/合同、客户资料编辑、文件、AI或新统计。它们仍留在总计划，未删除或提前标为完成。T03只覆盖已有商机推进事实和现有待办的可见性、办理接续。

## 设计门禁

E正常页面沿用；[G高保真](../../design/r2-sales-mvp/review/2026-09-15-g/index.html)覆盖加载/空/无匹配、只读、他人负责、未来等待、事项变化、撤权与读取失败，以及360px列表返回。G已于2026-09-15获用户确认；新增状态可按当前范围实施，无需重复批准。
