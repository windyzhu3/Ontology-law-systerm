# ADR-0016：R2 商机调度技术检查点

状态：R2 开发实施决定；不授予生产发布或验收资格。

## 问题

已确认 R2 计划要求异步接续可靠、历史回补有界且不改写 R1 Outbox。进程内待处理候选在重启后会丢失，尤其服务器已提交、响应丢失时，重新发现无法返回已退出的候选。

## 决定

正式追加 V890 / `52-plus-2-r2-v3`，仅新增 `platform_meta.r2_opportunity_checkpoint`。当前开发总数变为 52 张业务表加 3 张技术表，共 55 张；原 V001–V880 与历史 52＋2 发布证据保持不变。manifest、字段合同、精确散列与新增迁移权限验证同步演进。现有 README 的固定 54 表边界保留为历史合同，当前后继以本 ADR 和 R2-SCHEMA-SUCCESSOR 为准。

该表属于执行基础设施，由 Execution 技术端口维护，不提供新业务事实、不改变 Owner 或任务状态。Worker 只有本表读取、插入及正文/修订/数据库时间的列级更新能力。业务动作仍通过 mTLS API 和正式命令，不能凭检查点获得业务权限。

以完整服务绑定及扫描类型隔离状态；同一物理数据库会话上的 advisory try lock 避免多个实例同时推进，短事务在 HTTP 写请求前提交原命令意图。回执或后续存储失败时重启重放原命令。完整载荷摘要防止意外损坏，损坏或存储不可用停止派发。

## 取舍及边界

不复用部署状态、业务进展、命令槽或 R1 Outbox，因为它们具有既定事实/队列语义。进程本地文件不能满足多实例互斥及统一运维，因此使用现有 PostgreSQL 的独立技术表。连接必须是独占物理会话，不支持事务级连接池；轮询期间占用连接但不保持数据库事务。

表内诊断只是最近调度状态，不能代替主管异常台账。无效负责人发现与授权处置仍需完成，生产自动注册继续关闭。无页面或高保真变化，报价、合同、首款及案管边界不变。
