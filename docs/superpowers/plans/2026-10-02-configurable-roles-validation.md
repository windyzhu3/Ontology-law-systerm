# 可配置岗位验证记录

关联设计：[后台可配置岗位](../specs/2026-10-02-configurable-appointments-design.md)。实施基线：`5eded7f`；分支：`codex/configurable-roles`。

## 实现范围

身份管理新增“岗位管理”，支持创建、修改名称、停用、恢复。代码创建后不可修改；默认八类岗位只作为租户初始化数据。任职创建从租户启用目录单独分页选取岗位；任职列表、本人及代办选择从服务端目录读取名称。

岗位目录操作复用根组织 `IDENTITY_APPOINTMENT_MANAGE`、准确版本、幂等回执、审计和未决结果恢复。岗位不会自动创建授权；停用只禁止新增任职，已有任职及业务责任保留。不加入岗位权限模板、HR 功能或物理删除。

## 已完成验证

- 前端：111 个测试文件、1,123 项测试通过；TypeScript 类型检查及显式海华 OIDC 参数构建通过。
- 初次后端验证：28 项单元测试及 64 项集成测试通过，覆盖自定义岗位、名称显示、停用兼容、无自动赋权、失权、越租户、准确版本、并发和重放。
- 新增契约及升级保护：5 项契约投影/反例测试、2 项前端制品摘要测试通过；迁移生成确定性检查通过。原有 41 个迁移文件保持原字节。
- 完整升级前备份 `ROLE_CONFIG_BEFORE` 已保存于忽略的独立环境目录；新建 V1070 已执行 migrate/validate。升级前后原主体、组织、任职、授权、线索、商机、合同、转案和接收记录的数量及内容摘要相同，保留 10 个 HUMAN 任职和 8 个已接收案件。
- 独立评审指出前端构建摘要绑定不足，已修复为绑定完整 SPA 文件树和服务器文件，并在安装后再次核对；复核未发现剩余 Critical/Important。

实际登录发现共享候选的可选岗位代码被生成 DTO 输出为 `null`。实际 HTTP 响应及失败序列化测试已确认原因；仅对该可选字段使用 NON_NULL，不改变必需可空字段。本人及代办的会话候选仍保持 `id,label`，岗位专用候选保留 `id,label,code`。合成登录夹具显式初始化默认目录；旧会话字段计数断言对齐此前已批准的两个概览权限提示，并验证代办均无权进入。

## 保留的旧失败

完整数据库旧契约套件当前与归档基线 `5eded7f` 均为 116 项测试、相同 10 项失败。新增 schema 与 OpenAPI successor 采用固定摘要、准确历史投影及反例验证；剥离且仅剥离本次岗位接口后，完整 OpenAPI 与原基线相等。

旧基线结构性失败与归档基线一致；当前工作树另有此前未恢复的冻结视觉资源缺失。没有将这些失败改成通过，也没有绕过 main 合并门禁。此前完整业务 UAT 的性能和正式业务资料限制不属于本次岗位功能的通过结论。
