# R25_BUSINESS_OVERVIEW_V1（实施合同）

依据已确认 R2.5 的 R25-04 与 T 补稿，仅实现五项经营概览及同口径明细。当前实施中，未验收。

## 五项口径

业务期间以 Asia/Shanghai 的自然月为单位，默认本月；范围为月初含至下月初不含，当前月截至读取时点。先展示本月，接口接受明确月份以验证月边界。所有计数按当前本人 HUMAN 任职的准确来源授权重新核对；无查询资格显示不可查看，不能显示为零。

1. 新增线索：Lead 首次持久接入时间 created_at 落入期间，按 Lead ID 去重。输入的 captured_at 可为历史来源时间，不作为首次进入本系统的计数时点；重复命令重放不新增数量。
2. 有效商机：原有效联系形成的 Opportunity.created_at 落入期间，按 Opportunity ID 去重；后续跟进、报价版本和终止不会改写该形成事实。
3. 签署归档合同：原 signature_archive 证明必需签署核验与完整归档已完成；按对应 Contract ID 的首次归档时间计入期间，同合同版本修订不重复计数。未归档、只批准、只签署和仅执行条件核对均不产生该数量。
4. 已接收案件：原 Transfer ACCEPT intake 形成的唯一 Matter ID，按首次接收时间计入期间；退回、再次提交及分类更正不增加数量。签署不等于已接收。
5. 当前逾期待办：查询时仍 OPEN 或 WAITING 且原 original_sla_due_at 已过的 Task ID；WAITING 保留原 SLA 到期口径，单独标明等待，不据此生成或推断衔接异常。该项为当前时点存量，不套月内形成过滤。

## 权限与读取边界

- 不新增宽泛经营权限或统计真源，分别使用 LEAD_MANAGEMENT_READ、OPPORTUNITY_LEDGER_READ、CONTRACT_READ、TRANSFER_LEDGER_READ、TEAM_TASK_READ；商机同时保留原台账的 SALES_OPPORTUNITY_OWNER 本人当前责任路径，仅在当前承接人为本人时逐事实核对。入口提示取其任一本人查询资格。每条路径的明确拒绝优先，最后检查新鲜时间，全部审计成功并提交后才返回。
- 领域 Owner 只在自己的模块读取具名、有界计数候选；API 组合来源和组织。保留原冻结依赖 DAG，不用跨 Owner SQL 或读取加密正文后在浏览器计数。
- 商机及签署合同沿用原业务来源任职所属组织作为授权范围；跨组织责任交接不迁移业务可见范围。当前承接任职只用于本人责任路径核对。已接收案件沿用原转案查询的来源/接收组织规则。
- 计数与该指标明细共享同一候选、去重、期间与来源资格函数。数字只披露计数依据，不隐含读取其他历史正文的权限；明细仅解密已授权的客户显示名，进一步业务办理仍回原入口重新鉴权。
- 聚合候选每页最多 100，单次最多 5000；超过上限整体报告暂不可计算，不显示截断数字。明细默认 20、最大 100，游标绑定租户、人员、任职、指标、月份和页长，600 秒过期；拒绝隐藏总量泄露。
- 每次响应带查询时点；进入明细重新读取当前权限，期间内数据增加、责任完成或撤权可能改变结果，刷新后重新核对。不得用陈旧授权缓存保持旧数字。
- API 只在同一 OpenAPI 追加只读概览及指标明细；同一 SPA 按 T 的原样式展示。缺资格、失败、空结果与零值分开。无排名、金额合计、漏斗或 BI 扩展。

## 验证

先以 Owner 候选和准确月份/去重的失败测试驱动实现；再用真实业务命令形成固定合成样本核对五项、等待及终止、更正、原命令重放；验证明确拒绝、越租户、撤权、审计失败和委托拒绝。绑定当前源码/制品，保留 R25-01 性能失败、R25-02 和 R25-03 未验收边界。
