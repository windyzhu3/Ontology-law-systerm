# T05 连贯性验收矩阵

状态：开发验收完成，本地环境可供用户确认；不替代用户 UAT。范围来自 2026-09-18 T05 计划，设计依据为 E/G 与 I2。

| 场景 | 必须成立的结果 |
| --- | --- |
| R1 有效首联形成商机 | 来源名称、联系方式和需求作为待核对依据；不反写原首联、分配或来源事实 |
| 选择已有主体 | 仅展示有权主体；必须人工选择准确身份和版本，名称相同不自动合并 |
| 建立独立主体 | 自然人/组织，明确不是已有候选；联系人不自动成为委托方 |
| 参与方核对 | 至少一个准确委托方；未核实对方仅为待补充文字，无占位主体 |
| 草稿 | 可以缺项；不成为正式资料、不进入历史报价合同引用，不完成普通待办 |
| 正式确认 | 一次原子提交，完整参与方和需求形成不可变确认版本，审计和回执一起提交 |
| 共用资料修改 | 独立具名权限、明确影响；旧版本快照及引用不改变 |
| 原待办 OPEN | 确认资料后返回准确原任务，任务身份、SLA、既有进展不变 |
| 原待办 WAITING | 可以维护资料，但等待回执及时间不变，不提前恢复或产生重复任务 |
| T01 移交 | 旧身份草稿不能借新责任提交，重新读取当前负责人并恢复合法入口 |
| T04 结束并发 | 相同商机锁及版本裁决；结束后只读，不能确认旧资料或唤醒原任务 |
| 主体资料并发 | 拒绝旧版本确认，不静默覆盖、隐式更新或迁移历史引用 |
| 请求结果未知 | 锁定切换和重复提交，仅核对原幂等回执；恢复不发新业务命令 |
| 失权与读取失败 | 清除已失权数据，审计失败不返回正文；不退回假成功或缓存正文 |
| 冻结 UI | G 管理摘要、E 双栏资料卡；主操作唯一、低频折叠、小屏无横向溢出 |
| 后续消费边界 | 提供准确资料版本供材料、报价和合同使用；本轮不假建后续任务或按钮 |

验证分层：合同/Schema 后继校验、服务与真实 PostgreSQL 事务测试、前端交互测试、编译与生成一致性、浏览器对照。各层结果与真实链路见[实施验收记录](2026-09-19-t05-implementation.md)，按各层证据判定，不将全部异常路径声称为人工浏览器验收。
