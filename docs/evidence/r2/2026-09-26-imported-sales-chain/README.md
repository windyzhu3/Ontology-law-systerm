## 跨角色检查

- 直接合同申请：销售发起，不同授权人接收，销售不能代批；批准后授权待办完成，准备合同责任回到销售，开始准备保留原待办及 SLA；不伪造报价接受事实。
- 报价：发起、形成、提交不同审批人、批准交付、记录客户接受，再交付合同准备。原回执继续可读，原普通跟进不再活跃。
- 运行同一 API 进程，以不同受验证 JWT 身份办理。审批配置在隔离测试数据库中按既有不可变规则原子配置，不调整本地运行环境的授权。
- 材料使用真实合成 PNG 字节及 Owner 接收，恶意文件扫描为确定性测试端口；不能代替真实浏览器上传链验收。
