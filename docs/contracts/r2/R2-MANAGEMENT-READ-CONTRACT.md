# R2-M01 收款与转案管理读取

2026-09-28，依据已确认 R 高保真。仅补原合同台账查询，不改变收款、签署、转案、接收和分类命令。

- `PAYMENT_LEDGER_READ`、`TRANSFER_LEDGER_READ` 是可配置的任职授权；独立于 `CONTRACT_READ` 与办理授权。不按测试账号、角色名称或组织代码判断。
- `canReadBusinessManagement` 仅为直接 HUMAN 任职入口提示；无任职或代办时必须为 false。每个请求重新核对任职、有效期、数据范围与显式拒绝。
- GET `/api/v1/business-management/{view}` 与 `/{requestId}` 仅支持 payments/transfer。无请求正文；查询参数白名单、重复参数拒绝、禁止客户端租户头；所有响应 no-store。
- 候选扫描每次不超过 100 条，响应 1–100 条。按不可变请求 ID 做键集分页；游标 AES-GCM 保护，绑定用途版本、租户、主体、任职、视图、查询、状态、页大小，10 分钟失效。授权过滤可能产生空页但保留下一页；不返回全租户计数。
- 每条输出先核对商机、责任依据、线索标签、准确请求/工作流及不可变合同版本；实际责任人另外核对任职、主体、组织三个事实。无权限不展示姓名。
- 收款详情区分本次请求与合同版本累计，按币种分组；明确先款才显示结构化门槛。不将条件收费上限当应收，不把未达到门槛的部分到账显示成足额。存在撤销/退款时提示对照原记录，不输出误导性净额。
- 转案详情读取真实当前工作流、审查、接收、分类和准确补正项；案管接收前不生成案件标识。分类沿用既有案件，不新建案件。
- 办理按钮仅在当前本人任务开放且原 CONTRACT_READ 与命令授权均成立时出现。点击再读取当前请求，使用原 taskId 进入统一工作台，原命令再次鉴权。不创建第二套任务或办理表单。
- `READ_BUSINESS_MANAGEMENT` / `R2_MANAGEMENT_DISCLOSURE_AUDIT_V1` / `R2_MANAGEMENT_DISCLOSURE_V1` 为具名审计条目；只记录准确事实选择器和授权快照，无客户名、合同正文、金额或材料内容。共用业务读锁、身份授权锁，响应前重新检查所有披露依据，同事务同步审计；审计失败不能返回业务数据。
- 查询筛选只在同一有效会话对象的内存中保留，不写浏览器存储，换任职与过期后不继续显示旧详情。
