# R2 线索入口客户端基础 V1

状态：实现基础组件；尚未连接生产录入页面，不代表 R2-1 导入闭环完成。

依据：[已确认 R2 计划](../superpowers/plans/2026-09-13-r2-complete-sales-mvp-plan.md)。复用现有 `POST /api/v1/leads`、`CAPTURE_LEAD`、来源策略、权限与准确命令回执，不新增批处理平台，不改变案件形成后再分类的规则。

## CSV 预览

- 首批客户端限制 UTF-8 内容最多 1 MB、最多 200 条非空数据记录。表头必须唯一，来源记录与需求必须映射；姓名、电话、邮件可选。批次规模后续扩大须先核对实际交付需求。
- 支持 BOM、逗号、双引号转义、引号内换行；拒绝不闭合引号、含混列数或重复映射。公式形状作为普通文本，不执行。
- 解析支持引号内换行不代表业务字段允许换行：姓名/需求按既有 SafeText 合同提示控制字符错误；电话须为 E.164，邮箱做基础格式检查，服务端保留最终格式校验。
- 显示文件逻辑记录序号（含表头），保留可审阅值及逐字段错误，不截断超长正文；所有重复来源记录均标错，不静默选择其中一条。
- 来源记录键保留原值，不按行号或随机键重新生成；缺联系方式允许进入既有补齐责任。预览和字段校验不产生业务事实，后端继续执行正式校验、去重和授权。

## 录入及未知结果恢复

- 每次发送采用调用方保存的准确请求与命令 ID，使用当前本人任职和共享会话传输。通过公共 OpenAPI 接口提交，不访问内部 worker 路径。
- 与工作卡及管理写操作共用 RecoveryStore；未知命令存在时禁止发送另一行。只保存不含线索正文的恢复标记，正文仅保留在当前内存中。
- 仅准确成功回执或协议确认的失败结果可以释放当前写入标记。网络失败、未知结果、错配响应、缺失回执不当作“尚未创建”，不得自动使用新键重发。
- 恢复查询核对命令类型、命令 ID、当前 Actor 范围及结果事实类型；未决问题不靠客户端批量重试掩盖。

## 后续必需接线

受控来源接口、部署配置与前端读取方法已按 [来源合同](r2-lead-intake-sources-v1.md) 接通。来源读取不会占用或清除既有未决命令，响应必须禁止存储，过期会话不得采用返回目录。

逐行结果组件及批次恢复已按 [批次合同](r2-lead-import-batch-v1.md) 实现，CSV/XLSX 文件读取与预览已按 [文件预览合同](r2-lead-file-preview-v1.md) 实现。受控来源选择与显示名称、手工录入页面、文件选择/映射/预览的完整生产接线仍按 R2-1 计划继续。不得将基础组件标为完整导入交付。管理界面必须复用既有布局与 tokens，不把来源代码、内部枚举或案件分类作为用户录入负担。
