# R25_LEAD_MANAGEMENT_V1（实施合同）

依据已确认 R2.5 的 R25-03 与 2026-09-28 用户确认的 T 补稿。当前为实施中，接口和浏览器验收未完成。

- 在原管理模式增加早期线索查询、详情及受控来源查询；使用原 Lead、Party、Assignment、ContactResult，不建立第二份客户真源。
- 新增独立 `LEAD_MANAGEMENT_READ` 资格，仅当前本人 HUMAN 任职可查询；不会由录入、团队查询或合同权限自动获得。授权仍逐来源、精确版本和组织范围检查；明确拒绝优先，撤权立即生效。来源与责任人名称也分别授权。
- 原始来源组织作为未分配线索的组织依据；有准确分配时使用原分配任职的组织依据。来源无可信配置或原组织不可确认时不猜测可见范围。
- 元数据扫描最多 100 条，页面默认 20、最多 100。稳定不透明游标绑定租户、人员、任职、筛选和页长，600 秒过期；不披露未授权总数。权限过滤可能产生空页，提供游标继续扫描。
- 搜索客户名称或联系方式、来源、负责人及状态。受保护文本先授权再解密检索，并保留该读取的逐事实审计；最终再次检查新鲜授权，审计失败不给响应。读取事务不改变业务事实。
- 状态根据原责任、确认和关联商机事实生成，不仅凭 `disposition_code` 猜测；失败导入行没有 Lead 时不产生假记录。当前责任入口须核对原任务归属和原办理权限，纯查询资格不赋予代办能力。
- 客户名称优先使用有权的准确 Party；没有该锚点时显示原录入名称。不同合法接入保留不同 Lead；不能按名称合并。
- 来源只展示可信配置和授权内的分配结果，保持原指定/调配入口，不增加全局启停或规则编辑。
- 录入结果继续使用现有逐行原命令、回执及恢复流程，并明确是当次浏览器进度；本切片不增加持久批次表。

实施顺序：Owner 有界元数据与保护文本读取 → API 来源组合及授权/审计回归 → 同一 OpenAPI 的具名追加及会话入口 → T 页面与原卡/录入结果接续 → 多状态、多身份、恢复与三种宽度验收。性能和 M02 未通过部分继续保留，不因本切片推进而关闭。
