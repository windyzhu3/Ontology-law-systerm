# R2 商机到期跟进恢复 V1

本实现属于已批准的商机独立跟进责任接续，不增加用户页面或业务范围。

## 业务处理

R2OpportunityFollowupServices 组合 Opportunity、Identity、Responsibility 公开 Owner 口。调用者保有服务入口授权、业务事务栅栏、审计、回执和提交责任；此类本身不是 HTTP 入口或 Worker。当前不能把此内部能力计为生产自动唤醒已经上线。

恢复前锁定准确商机，确认商机未关闭、修订未过期；在身份锁内核对当前负责人仍为有效人类任职，并对商机、跟进任务、进展事实和来源线索分别检查当前权限。受保护进展需通过解密和摘要核验，租户、商机、事实身份及约定下一次时间须一致。处理后再次核对权限。

Responsibility 的专用 reopenOpportunityFollowup 入口锁定准确任务，核对 WAITING 状态、原商机及负责人、准确最新等待 ID / 摘要 / 任务修订、R2_OPPORTUNITY_FOLLOWUP_V1，以及与前序 DONE 任务完成事实一致的进展。以数据库 clock_timestamp 判断到期，调用方不能通过传入未来截止时间提前唤醒。

恢复仅将同一后继任务置为 OPEN 并递增修订，不创建任务、不改写原 SLA、不复制前一次草稿。原 R1 通用 reopen 入口拒绝商机类型，避免绕过上述核对；R1 联系和路由恢复继续使用原入口。

同一等待被并发或重复执行时只有一个状态变更成功，其余返回 STALE_TASK。正式命令层仍须提供相同命令键的回执重放；这里的原子防重复不替代公开幂等回执。调用事务失败会回滚恢复。

## 待接通的生产链路

接下来仍需独立后台服务授权、受限候选发现、正式激活/恢复命令与回执、Worker 派发和重试，以及历史商机接续。已有 R1 投影消费是只读权限，不能直接充当 R2 业务写入口。浏览器读取不执行创建或唤醒。

待上述链路完成后，再以真实后台任务验证“R1 有效联系创建商机 → 自动产生初始责任 → 人工进展确认 → 等待 → 自动到期恢复”。随后继续原定报价、合同、签署与案管接收范围。

当前接续状态（第二十批）：独立服务授权和受限候选发现已完成，正式到期恢复已接入命令运行时、审计和幂等回执，详见 [正式恢复命令 V1](r2-opportunity-recovery-command-v1.md)。首次激活正式命令、内部 HTTP / mTLS 传输与 Worker 派发重试仍待完成，生产自动唤醒尚未交付。
