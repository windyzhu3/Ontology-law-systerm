# R25_TEAM_MANAGEMENT_V1

R25-02 已批准 S 稿的具名读取后继，沿用一个 OpenAPI、原领域事实和同步管理披露审计。当前仍在实施，本文不代表 M02 验收通过。

- `GET /api/v1/team-management/{view}` 与 `/{recordId}`；四个视图为 `tasks / waiting / exceptions / history`，禁止写操作及任意租户、人员查询参数。
- 仅本人 HUMAN 任职使用独立 `TEAM_TASK_READ`。会话 `canReadTeamTasks` 只是入口提示，每次读取仍逐事实检查组织范围及 DENY。未选择身份、代办身份均不得取得此提示。
- 列表默认 20、最大 100；游标绑定租户、人员、任职、视图、筛选、页大小及 600 秒期限。候选、筛选和详情在同一业务/身份读取锁内完成；审计失败不返回正文。
- 36 个既有任务类型由 `R2TeamTaskResolver` 显式分组，新增类型必须补路径。原任务、责任依据、来源线索、等待及完成事实分别授权；转案历史解析原责任前序，不能读取新接手人的当前任务代替旧记录。
- 详情行动仅为回到原待办或原商机异常处置。团队只读权不产生代办权；历史/等待不提供完成按钮。`action=null` 时 `taskId / exceptionId` 同时为 null，两种行动的标识互斥。
- `WAIT_DUE` 仅表示到核对时间；不得直接映射成衔接异常。没有 taskId 的原领域 OWNER_EXCEPTION 必须独立读取，不能虚构任务。
- 历史确认人来自原决策、报价、合同、转案等具名事实；任职名称也要授权。缺少结构化确认人时明确缺失，不用当前责任人替换。不复制审计敏感正文到业务摘要。
- 前端复用 S/R 样式；迟到响应、身份切换、任务变化及失权清空旧详情；跳转原卡时再次读取，沿用草稿和原回执恢复保护。

`scripts/baseline/r25_team_transport_contract.py` 精确校验新增路径、schema、独立权限和入口限制，再投影回原 M01/R1 合同。原历史迁移、门禁及业务命令保持原有判定。
