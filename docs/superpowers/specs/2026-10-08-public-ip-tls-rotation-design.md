# 公网 IP TLS 跨 CA 轮换与持续可用性设计

日期：2026-10-08。状态：正式设计草案，待用户审核；尚未实施、测试或部署。

## 1. 目标、授权与边界

用户已选择将公网 IP 证书切换为 ZeroSSL，并要求长期可用；同意短维护窗口、临时并存旧新公网 CA、同步身份服务、应用入口和已有代理，验证后开放，失败保持安全。此选择授权编写本设计，不代表已批准实现或生产部署。

目标是在现有 Linux 控制器中增加正式、可审计、可恢复的公开 TLS 轮换路径。保留账号、密码状态、组织、任职、权限、业务数据、初始化 COMPLETE 记录及既有审计链；不重做初始化、不迁移业务 schema、不执行业务命令补偿。

本轮只编写文档，不连接生产服务器，不写实现，不提交或推送代码，不部署，不生成 API Key/EAB，不增加收费服务或云资源。私钥由用户在另行批准的执行阶段本地安全放入受保护目录；不进入聊天、文档、Git、日志或公开交付物。

长期可用指具备持续检查、提前取得候选、正式轮换和故障处置能力，不是保证 CA 永远免费签发或服务永不中断。未及时取得有效证书时必须如实报告阻断，不能关闭 TLS 校验维持表面可用。

## 4. 方案与不变量

选择“不可变 TLS 代次＋现有实例操作状态机”。不采用直接覆盖 certs/public.* 并重写原哈希，也不改造为共享热加载平台。

原 certs/public.*、http-trust.pem、identity-trust.p12、assembly/tls.json、settingsDigest 及初始化记录构成第零代，继续校验原字节完整性。历史证书过期不等于历史证据损坏；有效期校验针对将要使用的证书和连接。

新代次保存叶证书及发送链、私钥、准确锚集合、PEM trust、Java truststore、派生配置和 HMAC 清单。清单绑定 instanceId、operationId、父代摘要、原公开 origins、原发布摘要、文件摘要、证书指纹、有效期、来源证据、工具版本及验证结果。目录 0700、文件 0600，无符号链接。

证书私钥和秘密始终只存私密运行目录。公开结果仅返回操作 ID、阶段、非秘密证书指纹、期限、健康结果及脱敏失败代码。HMAC 提供现有本地篡改检测语义，不宣称能抵御拥有 journal key 的宿主管理员。

唯一有效 TLS 记录以原子写入、fsync 和 HMAC 保护，引用完整不可变代次。部署注册表的更改须由原操作意图对账；多文件写入不被描述为一个原子事务。新格式记录存在但损坏时拒绝启动，不能静默降级为第零代。

保留原始业务、身份和 SERVICE 配置；派生配置只能改变列明的 TLS 路径和必要启动关联。保持 JAR、SPA、schema、issuer、origin、端口、用户 UUID、SERVICE 指纹注册、授权和密码不变。需要其他配置变化时停止并扩大设计。

## 5. 信任锚准入与候选材料

### 5.1 根锚与链

准确 R46 根证书需来自 Sectigo 官方 HTTPS 发布渠道，记录来源 URL、获取时间、DER SHA-256 指纹，并与独立可信根来源交叉核验。只按名称相同、浏览器显示可信或上传者声明不能准入。正式操作只接受已审核的根指纹；任意上传 CA 不会自动加入信任。

区分叶证书、用于建链的中间证书与信任锚。上传 ca_bundle.crt 作为中间链输入。服务发送叶证书及所需中间链，不要求发送根。链验证禁用意外的系统默认根回退，以明确准入锚验证结果；另以系统信任验证外部兼容性，两种证据分开记录。

初次过渡锚集合为内部实例 CA、ISRG Root X2、经确认的 R46。这里有两个公网根加一个内部 CA。PEM 与 Java truststore 使用同一规范锚集合；Java alias 使用稳定指纹关联，逐 alias 导出核对 DER，不依赖导入命令退出码。生成后封存实际 PKCS12 字节，不要求重建产物天然逐字节相同。

### 5.2 证书、密钥与文件

安装前对实际暂存字节验证：PEM 格式、链顺序和签名、CA 约束、serverAuth、密钥可用且公钥匹配、有效期及两个原 origin 所要求的 SAN。IP 使用 IP SAN，不允许 CN/DNS 回退；保留严格 TLS 协议与验证。

默认候选最小剩余有效期 7 天；新证书到期须晚于当前证书。同一候选重复交付仅做一致性核对。短周期自动证书如需其他阈值，必须通过独立审核的策略变更，不能临时跳过检查。当前约 90 天候选适用默认策略。

检查绝对路径、父目录、属主、权限、普通文件类型；防止链接、硬链接别名带来的可变输入、FIFO/设备及检查读取竞态。先固定读取字节、封存摘要，再验证并安装这些字节。候选读取失败不改变有效代次。

手动导入是首版必须支持的完整路径：私密输入文件提供证书、私钥和中间链路径，以及已批准锚集合引用。用户无需向聊天传输私钥。错误信息不输出 OpenSSL/keytool 原始敏感 stderr。

## 6. 操作入口与状态机

拟在唯一入口 linux.py 增加 `public-tls-status`、`rotate-public-tls --inputs-file <private-file>`、`rotate-public-tls-resume --operation-id <id>`、`rotate-public-tls-rollback --operation-id <id>`。这是接口设计，当前命令尚不存在。恢复不能接受替换候选。新候选先完成无业务副作用的验证和持久化准备，再登记操作；登记崩溃留下的记录由原 ID 对账，不能产生第二个竞争操作。

新轮换仅从已完成原操作、准确已登记发布和 ACTIVE gate 开始。旧公开证书过期允许进入；原封存损坏、未知 gate、未完成发布/restore、实例归属异常仍拒绝。原证书已过期时，前置证明使用封存、资源归属、内部数据库和内部 TLS，不要求旧公网连接先健康。内部 CA 或内部服务证书失效不在此例外内。

所有执行及对账持有共享实例锁，gate 使用完整预期值 CAS；原操作日志只追加事件。拟定阶段如下：

| 阶段 | 准入与实际证据 |
| --- | --- |
| PREPARED | 原候选、锚、派生配置、上一有效代次、发布/gate、消费者和回退条件已封存 |
| MAINTENANCE_REQUESTED / MAINTENANCE | 先持久化预期 gate，再 CAS；已登记公共转发关闭，结果可观察 |
| STOPPING / QUIESCED | 停止入口及所有登记写入者并验证；数据库继续运行；保存稳定事实基线 |
| TRUST_PREPARED | 过渡 PEM/PKCS12、派生配置全部核对；以隔离客户端验证候选链，旧链仅在有效时验证 |
| SWITCHING / SWITCHED | 停止状态下安装身份 TLS 副本、选择新配置及代次，逐项对账实际文件和容器 |
| ACTIVATING / NATIVE_VERIFIED | 复用准确 ACTIVE CAS 和受控启动；外部转发仍关闭，实际原生握手指纹及完整内部健康通过 |
| PROXY_SWITCHING / READY_TO_OPEN | 已登记 nginx/Caddy 配置验证与加载，维护条件下用原地址身份完成逐跳验证 |
| OPENING / COMPLETE | 恢复已登记转发、端到端验证成功，记录完整证据；最终响应丢失只能重验同一操作 |
| FAILING / BLOCKED | 保留候选及诊断，关闭入口、停写并 CAS BLOCKED；失败清理中断也可续跑 |

旧新代次不并行运行两个完整应用栈。4GB 主机采用先停止后顺序启动，使用既有资源限制；不以新增内存、云实例或收费服务满足验收。不在本任务配置 swap。

当前 runtime_ready 要求 ACTIVE，因此激活时可能先恢复 ACTIVE 再启动验证，外部入口持续关闭；不声称所有内部写入都在健康验证后才发生。允许正常启动、会话、健康和 Worker 行为产生的技术变化须单独辨认，轮换本身不得改写业务事实。

## 7. 消费者同步与代理边界

身份服务保留原容器、realm 和数据库，增加只处理公开 TLS 的受控重启路径。不得为了换证重放用户导入、密码初始化、离线 bootstrap 或身份管理命令。

API/Worker 使用新代次 truststore 并重启加载；其原内部服务器密钥库、SERVICE 客户端证书和准确指纹注册保持不变。入口生成新 entry 配置，证书、私钥、CA 路径绑定同一代次；Node 必须重启。派生 binding/launch 对旧发布和父 TLS 代次作显式关联，登记替换容器，保留旧容器供对账；不能覆盖旧绑定或按名称收养容器。

HTTP helper、部署 health、启动/停止/发布/恢复路径均解析同一有效 TLS 记录。历史 operator.json 不改写；若只读身份检查仍依赖其旧 trust 路径，由受控读取层显式提供有效 TLS 引用，不得借机再执行 bootstrap。

代理接入限于已有、预先审核登记的 nginx/Caddy 服务和确定配置位置。登记清单包含服务身份、前后配置摘要、TLS/信任路径、加载与维护关闭方式、准确验证地址及原 Host/SNI/IP 身份。证书输入不得携带任意 shell 命令。未经审核不能自动登记或接管同名服务。

代理配置采用新代次引用并保存前一版本，配置检查通过才 reload；不要复制覆盖原封存证书。若代理使用系统根且无需改锚，也须证明新链严格验证通过并记录“不需改信任”的证据。nginx 不能验证 IP SAN 的既有约束继续由原 Caddy 桥接处理，不关闭任一段校验。

将来部署预检必须证明维护模式能阻止公开业务及身份转发，同时保留控制器在回环范围的精确探测。证书签发所需验证路径如需保留须明确限界。若现有服务无法安全提供该维护与探测边界，停止部署并修订代理适配设计；不能以绕过验证、偷偷直连公网或新平台代替。

## 8. 并发、崩溃、回退与审计

每项复制、容器启停、配置加载、代次指针变更和 gate CAS 均先落盘意图。超时/丢失响应按 UNKNOWN 处理：观察原容器、文件哈希、服务指纹、gate 和代理加载状态，匹配预期才推进；不把返回码当唯一证据，不重建账号或重放业务请求。

start、发布、checkpoint 恢复及另一轮换不能越过未完成操作。状态命令只读展示阻断原因和原 ID。并发 hook 返回 BUSY；输入不同的下一候选不能替换当前操作。文件系统满、HMAC 不符、未知服务或冲突 gate 均保留现场。

失败先进入 FAILING，再关闭转发/入口、停写、CAS BLOCKED。任一步失败继续保留 UNKNOWN 和明确未确认边界，不能报告“已安全关闭”。进程被强杀后不宣称存在无条件即时关停 watchdog：切换期靠已建立维护边界保持关闭；开放前所有准入已通过，开放后失去响应可能留下已验证服务，应由原操作重验。新增常驻监管器不在本设计范围。

回退是原操作内的显式选择，恢复整套叶证书、信任集合、配置、容器及代理关联，gate revision 单调推进，不改回历史 revision。只有旧证书及链当前仍有效、原代次完整且健康通过才可开放。旧证书已过期或不可验证时拒绝回退开放，继续原候选前向修复。候选本身在恢复前失效时保持关闭；首版不允许在原操作内随意换另一证书，须另行审核原操作收尾/候选替换设计。

审计保留父子代次、原操作 ID、阶段序号、预期与观测摘要、锚准入证据、健康证据和失败分类。保留旧材料于私密运行目录或既有 quarantine，不自动删除旧代次。TLS 回退不恢复数据库，也不撤销正常运行期间已经发生的业务事实。

## 9. checkpoint 与历史恢复

新 checkpoint 必须完整保存有效 TLS 清单、所引用材料、Java truststore、派生配置/launch 和代理期望状态；恢复证明验证同一集合。代理 live 状态不能仅凭恢复文件推断，必须由登记适配器重新核对。resources.json 本身不随资产恢复，恢复过程按已验证清单重建当前引用，保持实例资源归属及操作历史。

老 checkpoint 无 TLS 代次记录时明确解释为第零代，不能从当前 resources 猜测它使用了新证书。恢复保存现有代次到既有 quarantine，不擦除较新操作审计；历史引用定位必须绑定准确归档与摘要，不能搜索同名文件后收养。

**首版暂不支持从未完成 restore 内绑定新的证书轮换。** 恢复带回过期证书时，保留原 restore operationId，维持 RESTORED_MAINTENANCE/BLOCKED 和入口关闭；start 返回证书到期阻断，不伪造 COMPLETE，不另开轮换绕过原操作。解除该状态需要后续独立审核的“绑定 restore 的 TLS 变更”设计。

此限制必须在操作说明和恢复预检明显提示：有可用较新 checkpoint 时应在执行恢复前检查其证书有效性；不得把“完整恢复成功”误报为“服务已可开放”。本次支持的旧证书过期前向轮换，是已完成运行实例上的正式轮换，不包含未完成 restore。

## 10. 持续可用性、续期与阻断

### 10.1 首版必备：手动签发与同 CA 轮换

手动取得新叶证书及链后，经相同私密导入和验证流程轮换。只要仍链至已准入锚，无需再次扩大信任集合；完整轮换和失败恢复不因“同 CA”而跳过。链改用其他根、SAN 改变或 origin 改变时拒绝自动接受，要求独立设计/审批。

过渡期保留两个公网根；旧根退役不自动随下一次轮换发生。仅在消费者已验证、历史恢复风险已明确后，另行具名审核信任收敛操作。本首版不提供隐式删除旧根的行为。

### 10.2 状态、检查与提醒

public-tls-status 输出当前代次、原操作阶段、UTC 有效期、剩余秒数、期望/实测原生及代理叶指纹、各消费者验证结果、最后成功检查时间和续期来源状态。全链有效期也参与检查，不能只看叶证书；内部 CA/服务证书到期只报告为独立阻断，不顺便轮换。

默认提前 30 天 WARNING、14 天 ACTION_REQUIRED、7 天 CRITICAL；过期、未生效、指纹不一致或验证失败为 BLOCKED/UNKNOWN。退出码区分正常、需关注、阻断和检查未知，日志不包含秘密。检查证据超过 26 小时视为陈旧，不能显示最新健康。临近到期也须验证实际握手，而非只读磁盘日期。

提供使用现有宿主调度设施每日运行只读检查的文档与受控接入；其安装另属部署授权，不在本次文档阶段执行。记录本地脱敏结果与错误出口；只有明确配置并验证送达的通知渠道才能声称用户会收到告警。首版不创建收费告警服务，不将本地日志等同已送达通知。

### 10.3 自动签发接入的可验证边界

当前标记为 MANUAL_REQUIRED，不能宣称 ZeroSSL IP ACME 或无限免费续期已支持。自动签发适配器只有满足以下条件才可启用：官方支持范围与所用客户端版本已核验；账户免费额度/有效期/续签限制已确认；同一 IP 的实际签发和挑战流程有证据；凭据保管和调度获批；签发产物能通过同一导入验证。

不在本设计生成 API Key/EAB、购买额度或启用付费续期。免费额度未知、耗尽、外部 CA 故障、挑战失败、需要再次人工验证或用户再次签发时，显式记录 ISSUANCE_BLOCKED/MANUAL_REQUIRED，并按剩余期限升级提醒。签发失败发生在维护前时保留仍有效的现有服务；不得为了取得证书先停止线上服务。

已验证的签发适配器仅交付私密材料和来源证据，不直接改运行时。成功签发 hook 必须检查准确 lineage/来源绑定，固定实际材料后调用正式轮换入口。Certbot 的受控链接解析只允许准确登记的 archive 范围，再复制为私密普通文件；不能放宽核心输入的路径要求。

签发成功不等于部署成功；需分别保存签发、导入、轮换及端到端验证结果。重复相同产物进行只读幂等核对；未完成操作仅提示原 ID，不自动新建操作或替换候选。自动轮换的维护窗口及范围必须另有部署配置授权。

无新有效证书时，过期后严格 TLS 将拒绝连接，状态明确不可用；控制器拒绝开放或以过期证书重新启动。无常驻监管器时不保证到期瞬间停止所有已有长连接，这不构成继续使用过期证书的支持承诺。
