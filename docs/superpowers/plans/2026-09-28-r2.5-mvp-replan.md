## 2. MVP 终点与固定范围

业务终点保持：

`录入/导入 → 去重补齐分配 → 首联 → 商机 → 报价接受或直接合同授权 → 合同生成/审查/审批 → 人工签署核验/归档 → 执行条件 → 转案/补正/独立审查 → 案管接收并生成唯一案件 → 分类及明确承接`

- 两条合同入口都保留；直接授权不替代审批、签署或冲突审查。
- 仅合同明确约定先款时阻断转案；非先款合同保留独立财务责任。
- 接收后才分类为综法、执行或其他；更正不改变案件身份。
- 保留主动选待办、单张完整卡、草稿隔离、未知结果恢复及主管异常处理。
- 配套管理覆盖原 R2 十类最小能力；不要求十套独立页面。
- **字段提取、跟进摘要、材料缺项提示三项 AI 仍为 MVP 必需项**，全部人工确认，失败时可手工办理。
- 复用已确认 E/G 等母版及后续 P/P1/Q/Q1/R/S 设计；R、S 不重新申请同范围确认。尚未覆盖的新画面按已有要求先出最小补稿供确认。

MVP 之后再做：完整办案/庭审/执行/结案流程、总账/发票/税务/分润/薪酬、复杂 BI、动态审批或流程引擎、模板可视化编辑器、电子签和银行直连、多渠道通知、自动业务 Agent。全局来源启停不从当前“来源停止请求”功能中自动推导。
