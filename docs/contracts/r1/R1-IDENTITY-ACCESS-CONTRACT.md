## Identity and authentication profiles

`R1_AUTHENTICATED_IDENTITY_V1` is the unique verified HUMAN Principal in the configured Tenant, not a business Actor. It has no fabricated Appointment. Only getSessionContext may use this profile. Missing/ambiguous binding and non-ACTIVE Principal fail before a context response; unmapped refusal stays in IdP/security logging without a temporary Principal/Audit row. Tenant derives exclusively from fixed issuer/provider configuration; each realm/issuer maps to exactly one Tenant. Server computes Tenant-key HMAC of verified sub. Never match by display name/email or automatically bind/grant at first login. New HUMAN mapping needs no per-person deployment registration/restart. Existing exact SERVICE/mTLS registration remains unchanged.

`R1_IDENTITY_ADMIN_ACTOR_V1` requires active HUMAN Principal, own selected effective Appointment, active complete organization chain, current DIRECT management Grant at that same Appointment; no on-behalf pair, DELEGATED, OBJECT ALLOW, SERVICE or token-role substitute. All requested organizations must be the authorized scope root or its descendants. An ancestor is not a narrower scope. The request never chooses Tenant, caller Principal, caller authorization path, Grant proof, effective management permission, envelope or arbitrary command/table names.

Principal has no organization column: all ADM-01 operations and provider-user candidate lookup require Tenant-root scope IDENTITY_PRINCIPAL_MANAGE. ADM-03 new-Principal candidates and createAppointment require Tenant-root IDENTITY_APPOINTMENT_MANAGE because a new Principal has no organization anchor. Existing Appointment scoped reads may disclose only authorized in-scope rows. Do not infer whole-Principal control from one local Appointment.

All Principal/Appointment/Grant lists, candidates and target resolution are HUMAN-only. No online request may bind, appoint, grant to, mutate or disclose SERVICE through these pages. Existing SERVICE grants and registrations remain outside this contract. X-Appointment-Id is the optional authentication selector on all32 public Bearer operations; SERVICE cannot use it to alter its exact static binding. Its generated delegate parameter is contract compatibility only in Task9.1, with actual resolver enforcement pending Task9.2.
