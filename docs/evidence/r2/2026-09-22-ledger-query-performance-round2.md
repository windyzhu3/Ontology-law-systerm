# R2 台账查询性能：第二轮

## 范围

继续优化商机、合同列表及其共用查询链路。保持冻结页面、字段、记录范围、业务状态、实时授权和同步审计；不引入 Redis 或跨请求授权结果缓存。仅本地合成 MVP 环境，不代表 R2 发布验收或容量验收。

## 已定位的成本

1. 本地 HTTPS 验收服务只监听 `127.0.0.1`，而 `localhost` 也解析为 `::1`。Python HTTPS 客户端每次新连接先等待约 2.03–2.05 秒，再连接 IPv4；静态首页同样受到影响。Node 显式 IPv6 测试则直接报 `ECONNREFUSED`。这解释了先前 API 计时中的连接成本，不能推定所有浏览器采用相同回退策略。
2. 实际 17 条商机、9 条合同的读取分别执行约 3277 / 4405 次 JDBC SQL 调用。分段计时和 SQL 时间确认，来源读取与权限校验是主要成本，逐条同步审计也产生大量往返。
3. JFR 进一步识别出业务读取计时之外的等待：`CredentialIdentityRuntime.human` 在租户业务共享锁上等待后台命令。30 秒采样中观察到 8 次此类 SocketRead 等待，累计 7.381 秒、最长 1.101 秒。累计值来自并发线程，不是单请求耗时。身份映射、任职选择仅访问 identity 表，身份共享锁已保护它们，无须同时等待业务写锁。
4. 最近两分钟的后台命令审计显示 56 次 `OBSERVE_OPPORTUNITY_OWNER_EXCEPTION`。单个健康巡检的隔离测试执行 1201 次 SQL，其中持业务写锁后为 1133 次，租户身份行重复读取 107 次。仅移除身份映射中的业务锁不足以解决台账等待，因此同时优化这一后台命令的持锁工作量，保留巡检调度和业务锁本身。

## 调整

- 验收 HTTPS 服务分别监听 IPv4 和 IPv6 回环地址，保留 `localhost` Host 校验和上游 CA/主机名验证；未绑定局域网通配地址。
- 同一锁内读取 scope 按实际身份、代表身份、权限代码读取最多 257 条原始 DENY 记录。256 条以内复用原始记录并按精确类型、ID、revision/hash 匹配；超过上限回退原精确数据库查询，绝不截断拒绝规则。未来/过期记录均保留，每次判断仍读取数据库当前时间。
- 商机、报价和合同披露审计采用每批最多 128 条的参数绑定 JDBC 批处理。保留每个来源的独立审计内容、摘要、身份及授权证据，仍在原事务同步完成并等待提交。任一批失败，整个读取事务回滚。
- 身份映射和任职选择不再持有业务共享锁，仍获取独立身份共享锁。业务内容读取和命令执行继续使用原业务 fence；没有跨事务复用身份或权限结论。
- 仅为负责人异常观察命令，在业务排他锁获取后增加身份共享锁内的原始事实复用 scope。该命令不写 identity 表；按数据库当前时间逐次判断权限，scope 在提交前清除，数据库身份锁保留至提交。其他命令保持原路径。单例巡检 1201 → 383 次 SQL，持业务锁内 1133 → 315 次，租户身份行读取 107 → 1 次；隔离样本 SQL 执行耗时约 810ms → 255ms。
- 两类台账接入现有可选 `ols.read.metrics` 分段计时；日志仅包含随机关联标识、耗时和调用次数。验收代理亦有可选聚合计时，不记录请求头、令牌、对象 ID 或响应内容。
- 合同详情及下载回调显式使用 runtime 提供的事务连接，避免启用计时代理后绕过同请求事实复用。回归先发现 18 次共享锁请求，修正后恢复为业务/身份各一次。

## 验证证据

- IPv6 连接测试先失败，修正后 IPv4/IPv6 均通过；系统监听地址验证为 `127.0.0.1` 与 `::1`。
- 拒绝目录回归先观察到两个请求共 46 次查询，修正后为 2 次；并与未复用路径逐项比较授权结论和稳定依赖证据。
- 权限到期、未来 DENY、生效时间、精确 revision、超过 256 条时的精确 hash DENY 回退均通过。
- 批量审计测试先观察到 130 次写入，修正后最多两个 JDBC 批次；逐字段比较与单条审计结果，并验证后续批次主键冲突会撤销前面所有批次。
- 业务写锁阻塞身份读取的测试先出现 TimeoutException；身份变更的排他锁仍必须阻塞读取，提交停用后读取必须拒绝。
- 单记录隔离测试 JDBC 调用数：商机 109 → 93，合同 229 → 171；均保留业务与身份锁，不减少返回字段或披露来源。

日志：`output/ledger-denial-red.log`、`ledger-denial-green.log`、`ledger-batch-red.log`、`ledger-batch-green.log`、`ledger-credential-red.log`、`ledger-final-regression.log`、`ledger-observer-red.log`、`ledger-observer-green.log`。阶段计时：`output/ledger-phase-before.txt`；锁等待采样聚合：`output/ledger-lock-profile.json`。

## 实测说明

前次中位数商机 4.710s、合同 5.130s 包含上述客户端连接回退成本。本轮将修正后的完整 HTTPS 耗时与服务端阶段计时分别记录。使用同一账号、同一批 17 条商机和 9 条合同，比较完整 items，不比较含随机值的加密分页游标。

浏览器控制连接不可用，本轮不声称完成浏览器渲染计时；页面代码未修改。小样本顺序请求也不代表并发 P95 或完整容量矩阵。
