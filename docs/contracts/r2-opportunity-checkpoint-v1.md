# R2 商机调度检查点 V1

承接已确认的可靠接续范围。本批通过正式 V890 后继增加 platform_meta.r2_opportunity_checkpoint 技术表；保留既有业务表和 R1 队列语义，不新增页面。

检查点键为租户、服务主体、任职和 INITIAL / DUE 类型。证书轮换不创建新的业务进度，网络调用仍须通过当前证书及当前服务权限验证。正文采用版本化有界二进制编码，只保存候选准确引用、命令键、游标、页内位置、重试时刻及计数/最近状态；不保存客户材料或 HTTP 凭证。不使用 Java 对象反序列化。

每轮使用同一数据库会话的 advisory try lock 串行访问准确检查点，跨类型互不干扰；网络期间不持数据库事务。锁失效或存储不可用时停止派发。每次 HTTP 写请求之前先提交完整原候选及“结果可能不明”状态。回执确认和下一位置落库后才继续后续请求；若提交成功但回执或检查点更新丢失，新实例优先重放原键原输入。技术写入由 WORKER 狭窄权限完成，不能直接修改业务事实。

状态正文采用覆盖版本、类型与完整载荷的 SHA-256 摘要，先校验再解析；用于检测意外损坏，不替代数据库权限控制。正文损坏、版本未知、越界或存储失败均显示 STORAGE_UNAVAILABLE 并停止处理，禁止回退成空状态重新扫描。持久化会话关闭释放锁，不关闭共享 HTTP 客户端。已发出的请求在关闭时仍可能提交，重放依赖既有业务幂等命令。

本检查点保存最近调度诊断，不等同于完整的主管异常台账。负责人无效而被发现过滤的业务仍需独立异常发现与授权处置；该管理路径完成前，不注册生产循环或推进 R2 发布验收。

T01管理路径和T02正常周期总装已完成开发验收。当前可配置的运行组合、独立开关与启用边界见[正常商机周期总装](r2-opportunity-worker-assembly-v1.md)；生产默认关闭，开发验收不授予发布权限。
