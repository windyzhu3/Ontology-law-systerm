## 必须保持的约束

- 沿用现有顶部栏、单工作卡、管理侧栏与列表/详情布局；颜色、字体、边框、间距以现有 tokens 与组件为准，不把生成图中的微小渐变、字体偏差或图标细节当作新设计系统。
- 每页仅一个视觉主操作；列表中的“前往处理”回到现有工作台，不在管理页直接改业务阶段。
- 管理导航按实际权限显示，本包五个业务分组不替换原有身份管理入口；未覆盖的来源、分配、审计等仍在 R2 范围，不因图中未展示而删除，也不预先扩成新的后台平台。
- 工作台“我的待办”默认可收起。仅展示有权处理的事项；系统推荐不是唯一可选事项。存在未保存内容时，切换须允许取消或明确放弃；提交中、结果待确认时不得切换重放业务命令。
- AI 仅用于字段提取、跟进摘要、材料缺项提示。候选保留来源、待确认状态、编辑/忽略能力。未确认内容不得写入业务事实；不用 AI 时仍可手工完成。图中绿色主按钮表示层级，不代表任何前置条件下均可点击。
- R2-HF-02 的候选核对后才应用于表单，并展示已确认状态；改变来源文本使旧候选失效。联系人、手机号、客户名称不因示意图而变成全局必填；缺联系方式进入既有补齐路径。来源记录号遵循既有捕获合同，手工录入无需向用户暴露内部键；手机号提交前规范化及校验沿用接口规则。
- R2-HF-03：文件内相同来源记录号涉及的所有重复行均标错；图中相同客户或相同手机号不等于相同来源记录号。预览通过不等于入库成功。CSV/XLSX 不执行公式或宏。文件限制沿已确认合同，超限在提交前说明。
- R2-HF-04：核对原请求的结果，不创建新请求重复录入。已录入后的责任以服务器事实为准；可能处于去重、补齐、待分配或联系，不能一律宣称已分配销售。恢复入口不能跨用户/租户恢复，不承诺浏览器保存原始客户材料。
- R2-HF-06：忽略 AI 后仍需人工核对业务材料；上传不等于核验。合同明确要求先到账时阻断转案，否则催收并行。只有案管审核接收后生成唯一案件，再分综法、执行或其他。
- 正式报价保留；直接准备合同必须有准确授权，且不能绕过冲突审查、合同审批和签署核验。
- 小屏保持单列、原有折叠导航，详情不挤压成无法读写的窄栏；新增移动版关键状态仍须补图确认。键盘焦点、错误提示和恢复行为沿用现有组件规则。
- 不引入 HR、总账、复杂 BI、可视化流程平台、自动决策或电子签/邮件/微信集成。图中“粘贴邮件”仅指用户粘贴文本，不是渠道集成。
