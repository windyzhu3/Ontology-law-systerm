# R2 商机后台候选发现 V1

本能力用于已批准的首次责任激活、历史商机接续及跟进到期恢复，不增加页面、用户字段或管理范围。

## 服务权限

- INITIAL：当前选定 SERVICE 任职必须具有组织范围内有效的 OPPORTUNITY_TASK_ACTIVATE 直接授权。
- DUE：当前选定 SERVICE 任职必须具有组织范围内有效的 OPPORTUNITY_TASK_RECOVER 直接授权。
- 对象 ALLOW、委托、同主体其他任职或 R1_PROJECTION_CONSUME 不能替代对应授权。人类任职不能调用此服务发现能力。
- 每条候选同时检查服务权限及当前有效人类负责人的 SALES_OPPORTUNITY_OWNER 权限；商机、来源线索以及相关任务 / 等待 / 进展事实分别检查，对象 DENY 生效。

这两个权限名称用于内部服务发现及对应正式命令，没有为现有服务自动授予权限，也未增加管理界面的授权选项。

## 候选规则

INITIAL 从有权负责人名下的未关闭商机按创建时间及 ID 扫描，再通过 Responsibility Owner 查询初始事项是否存在。已有初始事项在任何状态均不重新发放，包括已完成和已取消事项。扫描不依赖原 R1 Outbox 的消费位置，能发现历史商机。

DUE 仅扫描已到数据库观察时间的商机 WAITING 后继责任。核对最新等待修订、R2_OPPORTUNITY_FOLLOWUP_V1、前序 DONE 责任、相同商机 / 负责人以及完成进展引用；商机关闭、修订变化、负责人无效或无权时不输出候选。正式恢复仍重新核对受保护进展正文、约定时间及所有写入条件。

每页 1–100 条扫描记录；按创建/到期时间及 ID 稳定分页。下一页位置取最后扫描记录，包含被拒绝或已存在初始责任的记录，避免反复卡在同一条。分页凭据使用 HMAC，绑定租户、SERVICE 主体、选定任职、扫描类型和观察时间，五分钟后失效。篡改、跨身份、跨类型及无界请求拒绝。

候选包含准确商机 / 任务 / 等待 / 前序进展引用、约定时间及稳定 UUIDv5 命令键，不含客户名称、联系信息或进展正文。命令键采用独立 R2_OPPORTUNITY_MAINTENANCE_KEY_V1 命名与标准 URL namespace，绑定候选类型及准确引用；它仅是后续命令的输入，不代表命令已经执行。
