# R2 逐行导入与结果恢复 V1

范围：R2-1，沿用 CaptureLeadV1、统一会话传输及未决回执保护。视觉依据为已确认的 R2-HF-04；不新增业务命令、后台模块或第二套样式。

## 已实现

- LeadImportBatch 接收最多 200 行已核对记录，保留原文件行号。错误行不发送；合法行固定请求键和来源记录键。构造时拒绝重复命令键、重复来源身份与无效行号；复制请求以隔离调用方后续修改。
- 单实例串行提交，避免双击并发。成功行与已有明确拒绝结果的行不会自动重提。收到明确失败时暂停；未知结果阻止继续，使用准确原命令的 GET 回执恢复。
- 恢复成功后不自动提交剩余行，需用户主动继续；恢复拒绝显示未录入。404、错误回执和本地标记被删除均不视为可以重发。
- 批次绑定原 actor scope，每次执行重验会话；中途会话失效/请求中断保留未决结果。其他事项占用共享恢复记录时暂停本批，不将其误认成本行回执。
- 原请求正文只保存在当前实例内存，浏览器存储继续只有既有四字段恢复标记。没有持久化整批正文、没有跨身份批次恢复或全批重试能力。
- LeadImportResults 为独立内容组件，复用管理页列表、详情、表格、按钮与 tokens；状态汇总、原行号和单个核对/继续主操作随真实批次结果更新。会话不匹配时隐藏批次内容。
- 结果页不凭录入回执声称已分配销售或已创建联系责任，后继责任仍以服务器工作卡事实为准。

## 接线约束及未完成项

目前未挂接生产路由。上层须先接通受控来源、CSV/XLSX 预览及业务授权，方可创建批次；不得从示例数据硬编码来源、任职、权限或业务分类。

构造函数不替代完整字段校验；调用方必须使用预览/字段合同，服务器仍作最终授权和校验。明确拒绝行的修正、请求键重用方式继续遵守原错误 retryPolicy，不以新键绕过原请求约束。

上层须按会话 scope/epoch 销毁批次和页面，导航/离开须接现有草稿与恢复保护。刷新后只有未决命令标记，不能宣称剩余整批材料可自动恢复。结果组件本身不提供授权导航、不读取后继任务、不建客户或案件真源。

尚未覆盖的选择文件、全成功/恢复后续状态与移动版高保真按设计清单先确认再正式放行；现有组件的基本状态更新不是对此后续视觉的批准。XLSX、来源选择、生产入口、台账读取、商机进展与三项 AI 均继续在原 R2 计划中。
