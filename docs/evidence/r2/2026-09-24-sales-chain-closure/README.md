## 本批修复

- 初始商机跟进补建同时检查报价与合同接管事实；扫描、正式命令和任务创建边界均有守卫。旧候选不能在合同责任形成后补回普通跟进。
- 合同准备申请、准备流程或合同已形成时，报价读侧不再开放重新报价，写侧在根对象锁内拒绝旧请求。
- 商机台账优先投影真实合同责任、负责人、期限和本任职可办理性；保留合法并行责任，不批量取消任务。相关元数据与负责人身份分别鉴权并留审计。
- 报价接受后沿现有合同入口继续办理，去除“合同功能尚未开放”的过时提示。
- 结束商机查询区分普通跟进与下游接管，不再因比较不同任务集合而稳定返回 412；真正版本变化和撤权仍拒绝。
- 横向架构检查发现原签署模块直接调用责任模块的业务时钟；移至既有 API 组合端口，原四个业务小时及继承期限规则不变。
