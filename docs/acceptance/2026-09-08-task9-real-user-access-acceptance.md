## 1. 通过条件

必须在同一最终构建上通过下面全部必需项，完成独立评审，并附实际执行用例、退出码、脱敏截图/日志和人工 UAT 记录。测试跳过、mock 身份、只有 API 请求层证据或只展示冻结图片均不能通过。原 75 项测试属于回归基线，不是新增验收的完成证据。

自动化环境必须运行真实 Keycloak、应用 PostgreSQL、API 和 SPA；等待恢复场景加入实际 Worker。目标账号通过 Keycloak 受控创建，目标 Principal/组织/任职/Grant 通过管理 API/页面创建，不用 SQL 插入这些目标身份事实。只允许一次性 bootstrap 初始化信任根。业务数据采用隔离合成资料，沿实际 capture/分配/后继命令产生责任，不直接把 Task 插成所需终态。

人工 UAT 必须由指定真实使用者自行输入凭据；自动化测试使用的可登录合成账号不能冒充人工 UAT。不得记录密码、完整 Token、私钥、原始 subject、HMAC、未脱敏个人资料。

## 7. 证据格式与完成判定

每个 ID 对应一条机器或人工记录：`caseId`、`buildSha`、`environmentDigest`、`executedAt`、`status`、`reportPath`，自动用例另有测试工具原始 case identity 与实际退出码，人工用例另有使用者别名和确认结果。环境摘要含应用制品、Keycloak/数据库镜像 digest、配置脱敏摘要、浏览器及工具链版本，不含秘密。

通过条件是全部必需 ID 有真实成功证据、无 skip/零测试/假占位、独立评审无阻断问题；修改认证/授权/状态代码后须重跑受影响项并绑定新构建。扩大后的 Task9 完成不等于 Task10、容量或整个 R1 上线完成。
