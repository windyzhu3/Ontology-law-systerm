## 沿用的设计约束

- 同一顶部栏、管理侧栏、列表/详情与单工作卡。采用现有 `tokens.css` 的石墨文字、绿色主操作、浅绿状态、浅灰边框、6px 圆角与弱阴影；不建立新的视觉体系。
- 产品区域最多一个绿色主操作。次级操作使用描边或文字；提交中主操作禁用。场景切换与 AI 状态选择只存在于顶部审阅栏。
- 1440px 桌面保留管理布局，360px 小屏折叠导航、表格转逐行卡片、映射单列，主要操作可读可触达；小屏不是新增功能范围。
- 业务分类仍在案管接收建案后进行。录入不要求填写案件类型、案件编号、任职 UUID 或内部来源代码。
- 未决请求、会话变化、来源撤权、未保存内容分别处理，不把“暂时查不到结果”解释为“尚未录入”。
- 文件正文和未提交行只在内存中；重载后不能承诺继续原批次。再次导入前核对台账，保留原来源记录号。
- AI 仍限字段提取、跟进摘要、材料缺项三项，并经人工确认；本包仅细化字段提取，不取消其余两项，也不新增自动决策或渠道集成。

## 页面接线前必须补齐的功能

以下是既有范围中的完整性要求，不能以原型或基础客户端完成替代：

1. **客户名称与联系人分开保存和读回。** 当前 `CaptureLeadV1` / `LeadImportField` 主要提供 `capturedName`，不足以证明两个字段能独立保存。接线前须沿业务 Owner 定义具名增量及读回验证；不得把两个字段映射到同一值、静默丢弃其一，或拼入需求描述冒充结构化保存。
2. **录入结果到后继责任的授权查询。** 当前批次客户端只确认录入回执；HF-12 的负责人、当前任务与期限尚需真实查询。无权或暂未取得时降级，不以假数据补齐。
3. **同一会话与恢复入口。** 手工/批量共用现有恢复保护，来源变化、退出/切换和未保存内容保护必须接通；刷新/登录恢复不能跨身份暴露材料。
4. **三类分支持续可处理。** 无联系方式进入补齐、有重复进入去重、无销售负责人进入分配/异常责任；不能只演示直接产生首联待办的一条路径。
5. **AI 候选到表单到业务保存分开。** 候选保留来源，可修改和忽略；材料变化失效，不自动写入；故障时仍可手工完成。原型不是 AI 已实现的证明。
6. **后续商机责任可执行。** 当前初始商机责任基础仍不能代替完整进展卡、后继跟进及可靠承接；录入入口增加后不得掩盖此断点。
