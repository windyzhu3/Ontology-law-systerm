| 状态 | 需要确认的呈现与行为 |
|---|---|
| 01 首次责任未落实 | 安排合格接手人后起算首次期限；不存在的旧待办不显示已交接 |
| 02 办理中断 | 原任职失效，有合格候选时允许受控承接；不是业务完成 |
| 03 到期未接续 | 保留原期限与逾期事实，不借交接重置SLA |
| 04 未来等待交接 | 只落实接手人，保持原约定时间，不提前可办理 |
| 05 无合格接手人 | 登记协调说明/下次核对；异常继续保留，不临时扩权 |
| 06 依据变化 | 清除旧人选及说明，重新读取；不沿用旧输入续交 |
| 07 处置权限撤销 | 有查看权时保留只读状态，移除交接输入和动作 |
| 08 查看权限撤销 | 清除客户列表/详情与未提交输入；仅显示访问提示 |
| 09 主管无法唯一确定 | 运营仅看授权组织、异常编号、类型及发现/核对时间，不披露客户正文 |
| 10 他人已处理 | 展示当前真实接手人，禁止重复交接；不冒充当前请求成功 |
| 11 接手人未来等待 | 工作卡母版展示等待与开始时间，不出现业务提交按钮 |
| 12 仅有查看权 | 可查状态，无处置主操作 |
| 13 无异常 | 仅说明当前授权范围无待处置异常，不宣称业务全部结束 |
| 14 查询失败 | 旧列表不冒充当前结果，有只读重新查询入口 |

正常交接、填写校验、核对后确认、提交中、未知结果核对和成功继续展示沿用 E 的已确认交互。顶部状态/响应切换仅是审阅工具；结果未知时禁止切换与新提交。F 用合成数据模拟回执查询，不能作为生产幂等证明。

## 实施与验收边界

T01 需要完整交付：真实异常发现与去重、授权查询/候选、具名交接和协调命令、持久结果和原回执恢复、管理页面、我的待办与发现流程接续。T02 的正常商机周期调度总装不因 T01 获得完成标记；T01 自身的异常发现和处置后继续必须可实际验证。

原Opportunity/Assignment来源不改写；交接不伪造业务完成；已有期限/未来等待保留；首次期限按业务日历开始；新负责人不得把旧草稿直接作为本次提交。角色资格和对象权限在读取/确认/恢复时重验。协调记录不能把异常结案。
