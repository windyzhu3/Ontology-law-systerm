# T03 商机台账读取与办理接续合同 v1

状态：IMPLEMENTED / DEVELOPMENT-ACCEPTANCE-PASSED。G 高保真已于 2026-09-15 获用户确认；沿用 E 冻结母版。权限登记不等于向真实身份授予权限，R1 PAUSED / R2 NOT_GRANTED 保持。

## 传输与字段

仅新增 `GET /api/v1/opportunities` 和 `GET /api/v1/opportunities/{opportunityId}`。列表接受 `limit`（1–100）、不透明 `cursor`、客户显示名称 `search`、`state`（OPEN / WAITING / NONE / CLOSED）；参数与响应以 OpenAPI 为准。拒绝未知或重复查询参数、GET 请求正文及冒充租户/身份的参数。身份沿用既有 Bearer 与当前任职上下文。

| 字段 | 事实来源与披露约束 |
|---|---|
| opportunity.id / revision | 当前商机准确标识与版本，仅作传输选择，不让用户输入 |
| customerLabel | 当前关联 Lead 的最小显示名称；准确 Lead / Party 及来源链授权通过后才解密，不读取电话、邮件或原草稿 |
| ownerLabel | T01 当前有效责任及任职显示事实；保留冻结来源 Owner / Assignment。不可披露时显示受限提示 |
| taskState / nextActionLabel / dueAt | 当前准确任务、等待回执和期限；台账读取不创建或恢复任务 |
| lastProgress.summary / occurredAt | 仅详情提供最近已确认进展；准确对象授权后才解密。不可见时省略，不解释为没有发生过进展 |
| canHandle / task | 仅详情提供；本人有效责任、准确 OPEN 任务和全部办理授权通过才返回 task 的 id / revision / etag |

列表响应为 `items` 与可选 `nextCursor`。详情包含同样的行字段，以及上述可选进展和办理判定。响应采用封闭字段允许列表，不返回全部历史、联系信息或内部诊断。

## 当前授权

`canReadOpportunityLedger` 是入口提示：直接 HUMAN 当前任职具有 `SALES_OPPORTUNITY_OWNER` 或具名 `OPPORTUNITY_LEDGER_READ` 才可能进入。每次请求仍核对当前身份及准确事实；不支持代办，不将普通工作台、异常处理或 SERVICE 权限解释为正常台账读取权限。

销售仅查看本人当前有效责任下的授权商机；台账读取授权按商机原始业务组织和准确事实范围核对。两种路径分别核验，增加无关范围的授权不得屏蔽原有合法销售路径。读取权限不等于办理权限。

来源联系、分配、已完成来源任务、当前 Lead / Party、商机、有效责任、当前任务及等待依据必须一致。最近进展和负责人显示信息分别授权；对象 DENY 不通过前端隐藏补救。真正可办理还须满足既有工作卡的负责人身份和草稿元数据授权。

## 查询一致性与审计

Owner 具名公开端口负责读取，API 不越层查询内部表。按创建时间与标识稳定扫描，每次有界。搜索只在准确授权后的客户显示名称上进行，不搜索不可见进展正文。扫描过但未匹配的已授权名称也记录披露审计。

游标使用认证加密，不暴露被跳过记录的标识或时间；绑定身份、查询、筛选、观察时刻和扫描依据，五分钟失效。依据变化拒绝旧游标并要求重新查询。扫描页可能没有可见匹配项但仍有下一页，界面保留下一页入口，不把本页空误称为全部业务为空。

读取使用既有租户业务栅栏及授权锁，响应前复核当前事实和授权。具名披露审计真实落库，提交获确认后才返回；失败不返回成功数据，不修改业务状态。

## 办理与界面

沿用 E/G 列表详情布局、字体、颜色和间距。只有一个办理主操作；等待、他人负责或只读时不显示办理按钮。手机提供返回列表，不增加新的业务表单。

点击办理沿用现有任务选择和工作卡，核对所选任务版本，不静默改为另一张卡。保留未保存草稿，提交中和未知结果保护继续生效。台账与工作卡切换后重新读取服务端事实；身份变化、撤权、读取失败与迟到响应不得保留旧客户详情。

不新增商机关闭、报价、合同、客户编辑、材料、AI、统计或案管能力。T01 负责交接，T02 负责自动建卡与到期恢复；本合同只提供可见性和办理接续。

## R2.5 已有责任来源补齐（2026-09-28）

已有“未收到回复”等待来源为准确的 `opportunity.followup_attempt`（ID + 正文摘要）。台账只使用它核对等待血缘，以原商机读取权限逐事实授权并记录 `OpportunityLedgerDisclosureEntry`，不披露尝试正文、不记为有效进展。精确 DENY 仍隐藏整条受限记录。

报价审批的 workflow/member 和合同接管来源分别由已有 `QUOTE_READ` / `CONTRACT_READ` 投影及对应类型审计负责。普通商机审计不冒用这两类事实；没有对应读取权限时清除下一行动、期限和办理入口。
