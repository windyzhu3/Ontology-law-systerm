# 2026-10-02 管理员退出后销售主管登录

实际旧制品复现：同一Chrome上下文以sys_manager01进入身份管理，退出并完成统一身份服务退出确认，再用sales_manager01登录及确认本人任职。登录成功，但页面恢复/admin/identity/principals；销售主管没有身份管理权限，显示“当前任职不能进入身份管理”，无法从该入口进入工作台。

原因：SIGNED_OUT路由保存先前页面作为登录目的地，没有区分初次匿名访问与已登录账号主动退出/其他标签页退出。

修复：主动退出先清理浏览器与内存的页面意图，再进入/login；已认证标签页收到退出通知也清理旧页面意图。初次匿名访问仍保留允许的目的地；任职确认、身份管理授权、编辑离开保护与原未知结果恢复线索均未改变。

单标签回归及广播退出回归分别RED复现旧目的地；最终会话、目的地、OIDC三组81项PASS，类型检查与配置构建PASS。独立同席源码复核无Critical/Important。

仅原UAT前端部署HH011，旧SPA/server完整保留在私有artifact-history/HH011-SPA-*，后端仍HH010。实际同一Chrome流程复验sales_manager01进入/workbench，不再出现身份管理拒绝。没有业务写入，也未给主管增加身份管理权限。

测试中首次定位错误把身份主体导航当作同名heading、漏处理统一身份服务的退出确认，脚本超时保留；补足实际步骤后旧制品准确复现。首次构建发现回归用例使用TestingLibrary不支持的exact参数，已更正再完成类型检查/构建；这些失败不计通过。

当前岗位代码仍为封闭清单，业务任职/组织/有效期/授权为数据库配置。系统管理员初始化岗位IDENTITY_ADMIN和管理授权另由引导流程建立，岗位本身不替代显式授权。

本修复不改变原整体验收FAIL、尚未执行的场景或已有CI门禁失败；main未合并。
